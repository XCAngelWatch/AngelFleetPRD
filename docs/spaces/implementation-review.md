## 工作包一 · 节点注册与首次可信采样

GA-02 至 GA-09 就绪后，由 GA-10 串起同一次注册、连接和采样。在 A、B 各运行一次，使用受限账户交叉读取，使用同时获准两边的测试身份切换页面。[请求、响应和消息样例](../go-agent-interface-contract.md) · [可下载的 JSON](../examples/go-agent-first-sample.json)

1. 用节点生成的私钥签署挑战，登记 `requestId` 和公钥指纹。注入注册成功但回包丢失，沿用原身份再签新挑战。对照绑定行、成功消费审计和 HTTP 状态。
2. 获取短期连接票据并建立 WSS，分别截取 journal 新 epoch 落盘、`ready`、`ready.ack` 和首次投递。重连时让旧 `ready` 迟到。
3. 提交两次 `node.inspect`，固定同一租户、节点和 incarnation。先取得 CPU 和内存，再让第二次只有 CPU 成功。按[两次采样后的无缓存验收](#两次采样后的无缓存验收)把每项读数追到自己的原始 Go 命令和采样时刻。

扩展仪表盘另取相同选择器的两次有效样本，注入累计增长、计数回退、时钟回退和选择器改变。该组验证磁盘与网卡速率，M1 验收看 CPU 和内存。[采样来源与缓存规则](../technical-design.md#72-节点采样怎样进入-xc-仪表盘)

## 实测记录

每次运行填一组：`runId`〔待填〕、时间和环境〔待填〕、租户／节点／incarnation〔待填〕、控制面／Go／connector／XC 构建版本〔待填〕、验证层级〔待填〕。请求附 `traceId`，命令附 `commandId`，云端投递注明直连或 outbox 补偿。本地试验将不适用项标为「不适用」。复制本次场景行，填入故障时点、观察值、脱敏证据链接和结论。

`UNCERTAIN` 用例需要同时看到原命令标识、实际状态 `UNCERTAIN` 和对账新增入口调用为 0。仍为 `RUNNING` 或测试漏采状态、调用次数时，结论填「待核对」并注明缺项。按同一命令对实际 Compose、Go 创建或恢复入口计数。

#### 两次采样后的无缓存验收

GA-08 提供控制面投影，GA-09 接入页面，GA-10 在隔离 Linux 节点执行以下步骤。契约和示例已定，三项实施及真机结论均待完成。[逐指标接口、请求与响应](../go-agent-interface-contract.md#53-逐指标读取与冷启动展示) · [联调样例 JSON](../examples/node-metric-read.v1.json)

1. **留存第一次采样 S1。** 在在线节点 A 提交 `node.inspect`。保存本次 Go 采集点实际产生的两项读数、单位、毫秒时间及命令标识，等待 `result.committed`。核对 D1 中两项最后有效值和来源都属于 S1。
2. **只让第二次的内存探针失败。** 在隔离测试构建上让下一次内存读取返回 `COLLECTION_FAILED`，CPU 继续读取真机。用新幂等键提交 S2，保存故障注入点、S2 原始结果及最终提交回执。S2 为 `SUCCEEDED`，其原始内存字段为 `valid:false`、`value:null`、`sampledAt:null`。记录此时的命令数，保持连接并暂停新采样。
3. **从空白浏览器会话读回。** 新建无历史数据的浏览器配置或隔离上下文，重新登录获授权账户，禁用 HTTP 缓存后直接打开 A 的概览。抓取带当前 `nodeIncarnation` 的 `GET /v1/tenants/{tenantId}/nodes/{nodeId}/metrics/latest`。记录 `200`、`Cache-Control: private, no-store`、`latestAttempt.commandId`、`projectionRevision` 和响应体。此时最新尝试为 S2，页面只读刷新期间新增采样命令应为 0 条。
4. **逐项核对并留证。** 把 D1 投影、刚收到的 GET、页面文字及可查看的来源命令，与相同命令的 Go 原始记录逐项比较。内存的过期提示应能与它的上次有效时间同时看到。证据附本轮 runId、两条命令 ID、GET 响应头 `X-Trace-Id` 和脱敏截图；实测缺少任一端时记「待核对」。
